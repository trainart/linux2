## Managing LVM <br>LVM-ի կառավարում

🧱 Logical Volume Management (LVM)

LVM is a flexible way to manage disk space in Linux. 
Instead of using fixed partitions, you create layers of abstraction:

* **🧱 Physical Volumes (PV)**: Real disk partitions or entire disks.

* **🗃️ Volume Groups (VG)**: Pools of storage made from one or more PVs.

* **📦 Logical Volumes (LV)**: Usable "virtual partitions" from VGs, mountable like normal partitions.


> Note: The `/boot` partition must NOT be on an LV, as bootloaders can’t read LVM.


✅ LVM Benefits

* 🔄 Resize/combine volumes even across multiple disks
* ➕ Add disks to extend storage
* 📊 Efficient space utilization

### /boot Must Be Outside LVM

🚫 Why `/boot` Must Be Outside LVM (Usually)

The `/boot` partition contains:

* The Linux kernel (vmlinuz)
* The initramfs/initrd
* The GRUB bootloader files

⚠️ Problem:

At boot time, before the kernel is loaded, only the bootloader (usually GRUB) is running — and bootloaders have limited capabilities. GRUB cannot reliably read LVM volumes, especially in older systems or minimal setups.

✅ Solution:

Create a separate, non-LVM `/boot` partition (e.g., `/dev/sda1`) formatted with a standard filesystem like `ext4`. 

This allows GRUB to:

* Easily access the kernel and initramfs
* Boot into the system cleanly

🔁 Analogy:

Think of LVM as a vault. The key (kernel/initrd) must be stored outside the vault so the system can unlock and use it.


🔒 LVM needs kernel support.	Bootloader runs before the kernel is loaded
🚫 GRUB limitations.	May not understand LVM without help
🛠️ Recovery simplicity.	Easier to fix boot issues with plain /boot


✅ Best Practice: 

Use a small `/boot` partition (~512 MB–1 GB) at the beginning of the disk.

⚠️Another Problem: 

Kernel updates, may get `boot` partition full !!! 
So if `boot` is separate partition, care is needed to check it has free space.

### PRACTICE

As can be seen above LVM can be used both with **entire disk** and its part - **partition**  

In example below we use one entire disk `/dev/sdc`, but create a partition on another one `/dev/sdd1` .

Check what we have initially
```bash
lsblk
```

Display information about physical volumes

> `-a` option shows **all** info, not only **active**

```bash
pvs -a
```

#### Physical volume (PV)

Initialize physical volume(s) for use by LVM
```bash
pvcreate /dev/sdc
```

Display again
```bash
pvs -a
```


Create 2 partitions on `/dev/sdd`, but we will use first - `/dev/sdd1` 

```bash
cfdisk /dev/sdd
```

Initialize physical volume(s) for use by LVM
```bash
pvcreate /dev/sdd1
```

Display what we have
```bash
pvs -a
```

#### Volume Group (VG)


Create a volume group

```bash
vgcreate VG0 /dev/sdc /dev/sdd1
```

Display volume group information
```bash
vgs -a 
```


#### Logical volume (LV)

Create a logical volume 

```bash
lvcreate -L10G -nLV5 VG0
```

Display logical volume(s)

```bash
lvs -a
```

Format logical volume

```bash
mkfs.xfs /dev/VG0/LV5
```

Mount somewhere

```bash
mkdir /data5
```

```bash
mount /dev/VG0/LV5 /data5
```

Check

```bash
df -Th
```

```bash
lsblk -f
```

Create another logical volume
```bash
lvcreate -l100%FREE -n LV7 VG0
```

Check

```bash
lvs -a
```

Format it

```bash
mkfs.ext4 /dev/VG0/LV7
```

Mount
```bash
mkdir /data7
```

```bash
mount /dev/VG0/LV7 /data7
```


#### Advanced 

Add a new hard disk to an existing Logical Volume Group
Initialize physical volume(s) for use by LVM & check if it appears in all physical volumes 
```bash
pvs -a ; pvcreate /dev/sde ; pvs -a
```

First add that physical volume to existing volume group VG0 & check if volume group extended

```bash
vgs -a ; vgextend VG0 /dev/sde ; vgs -a
```

Resize the logical volume - add 3G from free space
(`-r` is important to also resize underlying filesystem by running external program `resize2fs`)

```bash
lvresize -r -L +3G VG0/LV7 ; lvs -a
```


Resize the logical volume - reduce 2G 
(NOTE: Reducing size is dangerous and not supported on several filesystems, like GFS2 or XFS)

```bash
lvresize -r -L -2G VG0/LV7 ; lvs -a
```

Resize the logical volume - add 100% of current free space in VG0 volume group 
```bash
lvresize -r -l +100%FREE VG0/LV7 ; lvs -a
```

Check with other tools
```bash
df -Th
```


```bash
lsblk -f
```
